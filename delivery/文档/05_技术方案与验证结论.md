# 技术方案与验证结论

## 正式架构

```text
日期任务目录
  ├─ 待处理/*
  └─ 色卡/*
        ↓
Python build_plan：验证、SHA-256、中心取色、原图×色卡
        ↓
prepare_upload：EXIF校正、RGB、最长边2048、JPEG≤4MB缓存
        ↓
BatchProcessor：单线程、context隔离、checkpoint、request ID
        ↓
system curl：multipart POST /v1/images/edits
        ↓
Python：解析JSON/Base64、验证PNG、原子保存PNG、派生JPG
        ↓
CSV、JSONL、checkpoint、HTML审阅页
```

## API契约

- Base URL：`https://your-image-gateway.example`（公开示例占位；真实地址由`base_url`配置注入，不写入文档或Git）；
- Path：`/v1/images/edits`；
- model：`gpt-image-2`；网关成功响应可能报告`gpt-image-2-codex`；
- multipart字段：`model`、`prompt`、`image`、`response_format=b64_json`；
- Header：Bearer Key、fresh `x-client-request-id`；Key从环境读取，仅在每次调用期间写入权限受限的短期临时header文件并传给curl，调用后尽力删除；它不进入Git、持久配置、应用日志、终端/聊天、输出产物或curl argv。权限限制或清理失败属于需要Agent检查的本机安全卫生问题，不作“不可能留下本地残留”的保证；request ID只用于追踪，不是幂等键；
- 不传：mask、quality、size；
- 一次只上传当前原图；色卡只本地取色。

## Prompt

A是简短参考方案。B要求所有可见户外窗帘（远处、阴影、遮挡）完整换色，保护所有非主体对象，保持材质/褶皱/垂坠/透光/挂孔/轮廓/光影，禁止增删移动和改变构图。深/浅/高饱和目标色会追加保护规则。

B是默认生产方案；A是显式可选的个别复检方案，只在B结果不满足时对个别组合调用，绝不默认A+B双跑。

## 重试边界

- 只有429（明确限流）与确认连接未建立（curl exit 5/6/7 且 HTTP 0）允许安全补试；`max_safe_retries`硬限制为`0`或`1`，默认`1`，即最多额外补试一次、默认间隔30秒；
- curl进程无法启动是本地`fatal/rejected`，请求未提交，不自动重试；
- 503：默认按`uncertain`处理，不自动重试；
- 超时、上传后断线、408/409、其他5xx、2xx缺图或Base64损坏：`uncertain`，禁止自动重提；
- 400/401/403/404/413/422：`rejected`，停止。

## 关键交叉测试

### 已知历史样例，curl成功

- 1254×1254历史原图；A短prompt；curl；
- HTTP 200；77.9秒；有效b64 PNG；模型`gpt-image-2-codex`。

### 原httpx本地工具，观察到兼容性差异

- 0901原图压缩到2048×2048、0.53MB；B prompt；httpx；
- 空体HTTP 503；0.66秒。

### 1254历史成功处理图走httpx，同样观察到差异

- 空体HTTP 503；约0.67秒。

### 0901原始4K图走curl，成功

- 4096×4096、8.38MB；同一B prompt；curl直接上传；
- HTTP 200；60.7秒；有效PNG 1254×1254。

### 同一个工具压缩缓存走curl，成功

- 2048×2048、约0.53MB；同一B prompt；curl；
- HTTP 200；32.66秒；有效PNG 1254×1254。

## 排除结论

已排除：

- 1254/2048/4096分辨率；
- 8.38MB原图；
- 工具压缩缓存内容；
- B增强prompt；
- DSC00247目标色`#5F5B58 RGB(95,91,88)`；
- gpt-image-2整体不可用。

某次部署观察到传输客户端之间的兼容性差异：当时httpx快速返回503，而相同的curl请求成功。因此正式交接版采用“新架构＋system curl”，并把system curl作为该部署的验证适配器；这不等同于“httpx必然失败”，也不应作为普遍结论。

## 为什么仍然保留Python

curl只负责网络传输。纯Shell不适合可靠实现：笛卡尔积、图像取色/压缩、稳定ID、checkpoint、状态机、原子保存、PNG验证、JPG修复、报告和审阅页。Python提供易用性与安全性，curl提供该部署的兼容性。

## 当前限制

1. 稳定版真正行为是单线程，不提供并发；
2. CLI仅A或B，没有自动compare并排图；
3. 没有精确task ID筛选，A选择性调用需建立复检目录；
4. 没有自动视觉质量判定；
5. 上传压缩可能损失极细纹理；
6. 网关地址通过`base_url`配置注入，文档不写死真实IP/端口；若实际端点使用明文HTTP应注意传输风险并逐步迁移HTTPS；
7. API没有有效图片幂等键；
8. `--limit`限制计划前N项，不等于N个新增调用。
