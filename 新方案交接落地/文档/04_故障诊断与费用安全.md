# 故障诊断与费用安全

## 第一原则

先判断“是否可能已经进入上游”。如果可能，宁可停下也不要自动重提。`x-client-request-id`只用于追踪，不是幂等键。

## 状态处置表

| 状态/错误 | 含义 | 自动重试 | Agent动作 |
|---|---|---:|---|
| pending | 未提交 | 不需要 | 正常计划 |
| succeeded | 已有有效PNG/JPG | 禁止 | 跳过 |
| PNG有、JPG无 | 模型结果已在 | 禁止API | 本地补JPG |
| curl进程无法启动 | 本地fatal，请求未提交 | 否 | 修复本机curl/权限，不自动重试 |
| curl exit 5/6/7且HTTP 0 | 已确认连接未建立 | 最多1次 | 按配置等待、fresh curl再试 |
| HTTP 429 | 明确限流 | 最多1次 | 按配置等待 |
| HTTP 503 | 网关不可用 | 否 | 默认按uncertain：不自动重试，记录request ID并对账后决定 |
| 400/401/403/404/413/422 | 请求/认证/权限/体积问题 | 否 | rejected，修复后人工再开 |
| curl超时/上传后断线 | 可能已处理 | 绝不 | uncertain，停止并对账 |
| 408/409/其他5xx | 可能进入上游 | 绝不 | uncertain |
| 2xx但非JSON/缺图/Base64坏 | 可能已计费 | 绝不 | uncertain |

自动补试的配置硬限制为`max_safe_retries=0`或`1`；`0`表示禁用自动补试，`1`表示上述两类错误最多额外补试一次，不能配置更多次数。

## 环境问题

### 找不到Python

现象：`python command not found`或Windows找不到`py`。

处理：安装Python 3.10–3.13；Windows勾选Add Python to PATH；重新创建`.venv`。不要使用当前已知兼容性不明的前沿版本作为首选。

### 找不到Pillow

运行：`python -m pip install -r requirements.txt`。确保使用工具`.venv`中的Python，而不是另一个解释器。

### 找不到curl

macOS一般自带；Windows 10/11通常自带。运行`curl --version`。不要用httpx“临时替代”；某次部署观察到两者存在兼容性差异，system curl是该部署的验证适配器，这不等同于“httpx必然失败”。

## 目录和输入问题

### 缺少待处理/色卡

确认选中的是日期目录本身，中文名称完全一致。工具只读第一层文件。

### 全组合数量不对

核对隐藏/临时文件、扩展名、子目录。应为原图数×色卡数。数量未经用户确认不得付费执行。

### 颜色不对

检查色卡中心200×200是否有文字、边框、反光或混色。dry-run输出RGB/HEX后让用户确认。

### 压缩后仍超4MB

工具会降低质量并缩小；仍失败则停止。不要修改原图；可在配置中谨慎调整限制，但需确认网关允许。

## API问题

### 空体503

某次部署观察到兼容性差异：原httpx客户端约0.66秒返回空体503，而相同的curl请求在32–78秒成功；system curl被作为该部署的验证适配器。不要把这种差异描述成“httpx必然失败”。若正式curl仍出现503，默认按uncertain处理：不自动重试，记录request ID并对账后决定。

### 401/403

Key无效或权限不足。不要打印Key；确认当前进程是否安全注入、是否有图片模型权限。

### 413

上传过大。确认使用`生成图/缓存/压缩输入`，默认最长边2048、4MB。

### curl超时

标记uncertain。即使没有输出也可能计费，不能立即再试。

## 输出问题

### API成功但不是PNG

本地保存会失败。不要把JPG冒充PNG；记录响应和停止。

### PNG存在、JPG坏/缺失

重新运行即可从PNG本地修复，不调用模型。

### 输出比例明显变化

checkpoint会记录比例差异超过4%的警告；需要人工审阅，不应自动接受。

### 视觉质量差

技术成功不等于业务通过。保留结果，记录原图＋色卡；先考虑选择性A，不要直接全批重跑。

## checkpoint问题

### checkpoint损坏

工具会拒绝继续。先备份整个`生成图/记录`，人工检查JSON。不要直接删除，否则可能重复调用。

### failed_safe下次为什么又能运行

failed_safe表示明确未获得结果，接口恢复后可重试；但重新运行仍是新调用。先说明费用。

### uncertain如何恢复

1. 停止整批；2. 记录task/request ID；3. 查usage/服务端；4. 确认未扣费；5. 用户明确授权；6. 才可`--retry-uncertain`。任何一步缺失都不重提。

## 绝对不要做

- while循环重试；
- 对uncertain换request ID立刻重提；
- 把Key放进Git、持久配置、应用日志、curl argv、终端/聊天或输出产物；允许的唯一短期文件是工具每次调用创建的权限受限临时curl header文件，调用后尽力删除；若权限或清理失败，停止并让Agent检查本机安全卫生，不宣称绝对无残留；
- 把私有网关地址写死在代码、配置样例或文档中；
- 全量前跳过limit 1；
- 看到503就把workers提高；
- 把输出放回待处理导致重复编辑；
- 删除checkpoint来“重新开始”；
- 同时运行两个进程处理同一任务目录。
