# 完全小白用户手册

> 你不需要会Python、终端、API或代码。最推荐的用法是：你整理图片并告诉Agent目标，Agent代你操作本地工具。遇到不懂的提示不要猜，截图或复制原文给Agent。

## 1. 工具能做什么

把每张原图中的**户外窗帘**换成每张色卡代表的颜色，同时尽量保持：材质、纹理、褶皱、垂坠、透光、挂孔、轮廓、光影、构图、背景、家具、植物和其他对象。

如果放入3张原图和2张色卡，会产生3×2=6个任务。每个任务通常对应一次付费图片API调用。

如果只想换“一张原图＋一个颜色”，可用更简单的`一次性换色脚本`（见`一次性换色脚本/README_先看.md`），它只产生1次请求；批量工具才是默认生产入口。

## 2. 你只需要准备两类图片

建立一个日期文件夹，例如`0915`，里面的文件夹名称必须完全一致：

```text
0915/
├── 待处理/
│   ├── 场景1.jpg
│   └── 场景2.png
└── 色卡/
    ├── 深灰.jpg
    └── 藏青.jpg
```

- `待处理`：需要换窗帘颜色的场景照片；
- `色卡`：代表目标颜色的图片；
- `生成图`：不要提前创建也可以，程序会自动创建。

不要把原图和色卡混在一起。不要把旧生成结果放回`待处理`，除非你明确要再次编辑它。

## 3. 支持的文件

支持JPG/JPEG、PNG、WebP、BMP、TIFF。图片必须能正常打开，且宽高至少32像素。程序只扫描文件夹第一层，不会自动读取里面的子文件夹。

## 4. 色卡是怎么读取的

程序取每张色卡正中心200×200像素的RGB平均值，再计算HEX和中文颜色描述。色卡不会作为第二张图上传。因此：

- 让色卡中心区域尽量是干净、均匀的目标颜色；
- 不要让中心有文字、反光、边框或其他颜色；
- 色卡太小也能取中心区域，但不推荐。

## 5. B和A怎么选

### 默认先用B

B规则更完整，会要求所有可见窗帘都换色，并保护背景、家具、植物、木结构等。适合正式批量。

### A只在需要时使用

当B结果过度约束、不自然，或某个组合需要备用效果时，再只对该组合调用A。绝不默认每个任务都生成A+B，否则费用接近翻倍。

推荐流程：

```text
全部任务先B → 打开审阅页检查 → 标出不满意任务 → 只补A → 最终挑A或B
```

## 6. 第一次使用怎么办

把`03_可以直接复制给Agent的话.md`中的“第一次接手”提示词发给Agent。Agent应按顺序：

1. 检查Python、curl和Pillow（不收费）；
2. 运行离线测试（不收费）；
3. `--dry-run`核对数量和颜色（不收费）；
4. `--prepare-only`准备压缩缓存（不收费）；
5. `--limit 1`只生成一个任务（可能收费一次；503默认按uncertain停止，不自动重试）；
6. 让你看第一张结果；
7. 你确认后才继续全量。

## 7. 怎么看结果

结果会出现在任务目录的：

```text
生成图/
├── B增强方案/
│   ├── png/          ← 模型原始PNG母版
│   ├── jpg/          ← 从PNG转换的网页/日常版
│   └── 审阅页.html   ← 双击浏览
├── A参考方案/        ← 只有运行A时才有
├── 缓存/压缩输入/   ← 上传副本，不是最终图
└── 记录/             ← 日志、断点、CSV、请求ID
```

重点检查：

- 是否所有窗帘都换色；
- 是否误改植物、家具、墙面、窗帘杆；
- 褶皱、透光和材质是否自然；
- 深色是否死黑，浅色是否过曝；
- 是否增加/删除/移动了物体；
- 构图和比例是否保持。

## 8. 中途关闭、断网或电脑重启

不用从头开始。程序会检查已有PNG/JPG和checkpoint：

- PNG+JPG有效：跳过；
- 只有PNG：只补JPG，不调用API；
- 没有结果：继续处理；
- uncertain：默认跳过，防止重复扣费。

直接把情况告诉Agent，让Agent检查`生成图/记录/`后续跑。不要删除`生成图/记录`。

## 9. 费用安全（一定看）

- `dry-run`和`prepare-only`不调用API；
- 正式调用前工具会显示“预计新增调用”；
- 没有真正幂等键，request ID只是追踪号；
- 如果状态是`uncertain`，请求可能已经生成/计费但结果没收到；
- **不要自行加`--retry-uncertain`**；
- 只有HTTP 429或确认连接根本没建立（curl exit 5/6/7且HTTP 0），工具才允许最多额外补试一次；503默认按uncertain处理，不自动重试；curl程序无法启动是本机错误，也不自动重试；
- 任何全量运行都应先成功测试1个任务。

## 10. API Key是什么，怎么处理

Key相当于付费密码：

- 不要写进Python、持久JSON/配置、Markdown、截图或聊天；
- 不要放进交接文件夹、Git、应用日志、curl命令行参数或输出产物；
- 由Agent从当前进程环境读取`SUB2API_API_KEY`且不得回显；工具仅在每次调用期间把Key放进权限受限的短期临时curl header文件，并在调用后尽力删除；
- 如果临时文件权限限制或清理失败，视为本机安全卫生问题，停止并让Agent检查；不要相信“绝对不可能留下本地残留”的保证；
- 如果你不确定，告诉Agent“请从已授权的本机凭据来源安全读取，不要打印，并检查临时header文件权限和清理结果”。

## 11. 常见情况

### “缺少待处理/色卡”
文件夹名或选择的目录不对。把日期目录结构截图给Agent。

### “缺少API Key”
环境没有临时注入Key。不要把Key发聊天，让Agent按安全方式配置。

### “HTTP 503 <empty body>”
网关暂时不可用。工具默认按uncertain处理并停止，不自动重试；先把request ID和日志交给Agent对账，再决定是否继续。不要循环运行。

### “uncertain”
立刻停止。把request ID和日志交给Agent，确认费用后再决定。

### 有PNG但没有JPG
重新运行会在本地补JPG，不收费。

### 结果不好看
先不要删除。记录原图名和色卡名，让Agent判断是重跑B、选择性A，还是调整规则。

## 12. 你可以始终这样对Agent说

> 我完全不懂Python，请你代我操作，不要只给命令让我自己猜。每一步先解释会不会收费；先做离线检查，再只测试一个任务；看到uncertain立即停止；全量之前必须让我确认。
