# 新方案交接落地｜先看这里

## 这是什么

这是“主体换色”的现场交付包，落地时默认示例主体为户外窗帘（可用 `--subject` 改成任意主体）。它面向两类人：

1. **完全不懂Python的用户**：只负责把原图和色卡放进正确文件夹，然后用自然语言让Agent代操作；
2. **接手的新Agent**：负责环境安装、离线预检、单任务探测、正式批量执行、断点恢复、结果解释和故障处理。

用户不需要学习代码，也不应该独自处理API异常。采用本地方案，是为了让任务状态稳定保存在本机，并让每次API请求只有“当前一张原图＋当前完整prompt”，不是为了取消Agent协助。

定位：仓库根目录 `subject-recolor` 是更早的工程基线；本目录 `新方案交接落地/` 是后来因为完全小白用户不会操作工程命令行而新增的 Agent 代劳生产交付版。

## 两个正式入口

### 默认生产入口：批量工具

`正式工具_batch_recolor_tool/`用于一次处理多张原图×多张色卡、需要断点续跑的正式生产场景。

### 快速试一张：一次性换色脚本

`一次性换色脚本/`只做“一张原图＋一个颜色＝一次请求”，没有笛卡尔积、checkpoint、CSV和并发，用于快速试一张或只有一个图一个颜色的最简落地。

日常不要使用`历史参考_不要作为主入口/`中的内容。批量工具采用：

- Python：扫描、取色、压缩、任务计划、checkpoint、重试策略、保存和审阅；
- 系统curl：作为该部署的验证适配器发送multipart图片请求；
- 默认B增强方案；A是显式可选的个别复检方案，绝不默认A+B双跑；
- 稳定版固定单线程；
- PNG保留模型原始字节；JPG只从PNG转换，quality 85、progressive；
- 每次调用只有一张原图，不上传色卡、不使用mask。

## 用户平时只需要做什么

创建日期任务目录，例如：

```text
0915/
├── 待处理/   ← 放所有原图
└── 色卡/     ← 放所有色卡
```

然后告诉Agent：

> 请按“新方案交接落地”的正式流程处理这个日期目录。先检查环境和输入，默认B方案，先dry-run和prepare-only，再只测试1个任务。我确认结果后你再继续全量。不要盲目重试uncertain。

模板位于：`任务目录模板/`。

## 最重要的规则

1. **B优先、A选择性调用**：不要默认全量生成A+B，避免双倍费用。
2. **先离线、后单测、再全量**：环境检查 → dry-run → prepare-only → limit 1 → 人工确认 → 全量。
3. **单线程**：当前稳定版固定为1，不要擅自开发或启用并发。
4. **uncertain绝不盲目重试**：读取超时、上传后断线、成功响应缺图等可能已经计费；先按request ID对账。
5. **Key不进入Git、持久配置、应用日志、curl argv、终端/聊天或输出产物**：工具从环境变量读取，仅在每次调用期间写入权限受限的短期临时curl header文件，并在调用后尽力删除。若权限限制或清理失败，应作为本机安全卫生问题停止并交由Agent检查；不要宣称不存在任何本地残留的绝对保证。
6. **503默认uncertain**：不自动重试；只有HTTP 429或确认连接未建立（curl exit 5/6/7且HTTP 0）才允许最多一次安全补试。curl无法启动是本地fatal，不重试。
7. **request ID只用于追踪**：它不是幂等键，不能作为安全重提依据。
8. **不要覆盖原图**：程序只在`生成图/`写缓存和结果。
9. **不要把色卡当第二张输入图上传**：颜色只在本地提取后写入prompt。
10. **不内置私有网关**：运行时通过配置、`SUB2API_BASE_URL`或`--base-url`注入。
